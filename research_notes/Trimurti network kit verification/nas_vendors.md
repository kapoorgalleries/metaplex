## Q1. Default web-UI ports and discovery tools (Synology 5000/5001, Assistant, find.synology.com; QNAP 8080/443, Qfinder Pro; TrueNAS 80/443); 2025–2026 changes

### Takeaway
The kit's ports are right (DSM 5000/5001, QTS 8080 + HTTPS 443, TrueNAS 80/443), and no 2025–2026 port change was found. Two script fixes are warranted: (1) `nas-check.sh` only curls `http(s)://$NAS/` for its vendor grep, but QTS has had URL redirection from port 80 to 8080 disabled by default since QTS 4.5.4.1715, so the QNAP branch of the grep never sees a QTS page — it should also curl `:5000` and `:8080`; (2) the script's default SSH user `admin` does not exist as a usable login on a default TrueNAS install (`truenas_admin`, root password disabled) and is the account both Synology and QNAP tell you to disable.

## Q2. Enabling SSH and key-based login (Synology, QNAP, TrueNAS SCALE)

### Takeaway
Synology: Control Panel → Terminal & SNMP is right; the 755 home-directory rule matches the widely used guides (Synology's own KB text could not be read), and the kit should add the `.ssh`/`authorized_keys` modes and the "administrators group only" rule. QNAP: the table's path is missing the "Network & File Services" level, only administrator accounts can SSH, and you must add the named admin under "Edit Access Permission". TrueNAS: the SSH service is off (port 22 closed) by default; "Allow Password Authentication" + per-user "SSH password login enabled" is only for password logins; key logins need the user to have a home directory and shell, with the key pasted into the user's Authentication section; iXsystems recommends keys only.

## Q3. SMB compatibility with Windows 11 and current macOS

### Takeaway
The kit's "Windows refuses SMB1 and guest" is correct and can be sharpened with dated facts: Windows 11 ships without SMBv1 client or server, Windows 11 Pro blocks guest logons from build 25267 (24H2) onward, and Windows 11 24H2 / Server 2025 **require SMB signing** by default — so the NAS must support signing (all three do). NAS-side: Synology's signing option is "Server signing: Disable / Client defined / Force" (there is no "auto"); QNAP's path is Win/Mac/NFS/WebDAV → Microsoft Networking → Advanced Options with Lowest/Highest SMB version (SMB1 off by default since QTS 5.0.1); TrueNAS has only a **Minimum Protocol** (default SMB2, no maximum) in System → Services → SMB, and guest access is confined to pre-25.10 "Legacy Share" presets. `cmdkey`/`net use` syntax in the kit is correct.

### Cited Findings
- **Kit says:** "Windows 10/11 refuses **SMB1** and **guest** (passwordless) access by default, and caches old credentials. macOS is fussy about signing." / "**Protocol**: on the NAS set min SMB2, max SMB3. Never re-enable SMB1 on the PC." / "**Guest**: turn guest access off on the NAS; create a real user per person and mount with it." / "**Stale Windows credentials**: `cmdkey /list` → `cmdkey /delete:nas` (and the IP form) … Mapping: `net use N: \\nas\share /user:nas\sanjay /persistent:yes`." / "**macOS**: Finder → Go → Connect to Server → `smb://sanjay@nas.local/share`. If it hangs, check the NAS's \"SMB signing\" setting (leave \"auto\") and that the Mac resolves `nas.local` (mDNS on the NAS)." ## Q4. Degraded / crashed volume handling per vendor; hot-swap; single-parity risk; scrub and SMART scheduling

### Takeaway
Synology distinguishes "Degraded" (still accessible, repairable via Storage Manager → Repair after swapping the drive) from "Crashed" (repair unavailable; restore from backup) and permanently drops a crashed pool from scrub schedules. QNAP's states are Degraded (→ Rebuild RAID) versus Error/Not active (→ Recover RAID), and QNAP says to back up before replacing and recommends monthly RAID scrubbing. TrueNAS: offline the failed disk first, replace with same-or-larger, auto-resilver; a default weekly Sunday 00:00 scrub is created per pool; SMART tests must not be scheduled on scrub days. The kit's paths need tightening (Synology "Schedule Data Scrubbing" and "HDD/SSD → Test Scheduler"; QNAP "Global Settings → RAID Scrubbing Schedule") and "quarterly scrub" should become "monthly" for QNAP.
