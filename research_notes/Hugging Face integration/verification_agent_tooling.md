## Refuted claims

### R1. Gemini: `httpUrl` is not the preferred "documented form"; the CLI marks it deprecated
- Claim (Q3, "`httpUrl` form" and Recommended configuration §3): "The docs define `url` as the SSE endpoint URL and `httpUrl` as the HTTP streaming endpoint URL. The CLI instead writes `url` plus `"type": "http"`." … "HF's own `gemini-extension.json` uses the documented form" and the proposed project file uses `"httpUrl": "https://huggingface.co/mcp"`.
- Contradicting source: `@google/gemini-cli@0.61.0`, `bundle/chunk-5FZXKDXH.js`, `createUrlTransport` (line 376102 ff.): `MCP server '${mcpServerName}': Both 'httpUrl' and 'url' are configured. Using deprecated 'httpUrl'. Please migrate to 'url' with 'type: "http"'.` The transport code treats `url` + `type: "http"` as the current form and `httpUrl` as the deprecated one. The docs page (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/tools/mcp-server.md, lines 159-161) still lists `httpUrl` without a deprecation note, so the note's reading of the docs is faithful, but the framing ("the CLI *instead* writes …", "documented form") is backwards.
- Correct fact: `httpUrl` still works in 0.61.0 (the warning only fires when both keys are present), but the non-deprecated form is what `gemini mcp add -t http` writes: `{"url": "https://huggingface.co/mcp", "type": "http", "headers": {...}}`. The proposed `.gemini/settings.json` should use that shape.
- Impact: changes-code (the proposed `.gemini/settings.json` block).

### R2. Codex npm `alpha` dist-tag has moved
- Claim (Q2): "`npm view @openai/codex` shows `latest` = `0.156.1` and `alpha` = `0.157.0-alpha.11.1`."
- Source: `npm view @openai/codex dist-tags` (registry.npmjs.org, 2026-09-24 ~23:50 UTC): `latest: '0.156.1'`, `alpha: '0.158.0-alpha.11'`. `npm view @openai/codex time`: `0.157.0-alpha.11.1` published `2026-09-24T22:05:20Z`, `0.158.0-alpha.11` published `2026-09-24T23:35:01Z`. The note was correct in the ~90-minute window between those two publishes; it is stale now. `latest` is unchanged.
- Impact: cosmetic.

### R3. `hub/agents-skills.md` does not say `hf-cli@huggingface/skills`
- Claim (Q5): "hub/agents-overview.md, agents-cli.md, agents-skills.md and the repo README all say `/plugin install hf-cli@huggingface/skills`."
- Source: `hf://docs/hub/agents-skills.md` says `/plugin install <skill-name>@huggingface/skills`. agents-overview.md, agents-cli.md and the README do say `hf-cli@huggingface/skills` (README line 36).
- Correct fact: the marketplace reference `…@huggingface/skills` is common to all four, but agents-skills.md uses a generic `<skill-name>` placeholder. The note's substantive point (the marketplace must be referred to as `huggingface-skills`, its `marketplace.json` `name`) is unaffected.
- Impact: cosmetic.

### R4. `sourceUrl` is written for `gitlab` sources as well as generic `git`
- Claim (Q6): "`sourceUrl`: written only for generic git sources, so they can be restored."
- Source: `skills@1.7.0` `dist/cli.mjs` line 4533: `function getProjectLockSourceUrl(sourceType, sourceUrl) { return sourceType === "git" || sourceType === "gitlab" ? sourceUrl : void 0; }`.
- Correct fact: written for `sourceType` `git` **or** `gitlab`; still never for `github` or `local`, so the conclusion about this repo's entries stands.
- Impact: cosmetic.
